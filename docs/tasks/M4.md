# M4 任务

目标：内测用预建账号登录，草稿、设置和运行历史按账号隔离，运行可归档、可取消归档，并有留存与备份流程。M4 的验收是本地多账号隔离与数据生命周期可跑通；真实 HTTPS、目标网关和跨标签会话在 M6/M7 验收。

契约：[REST API 的 M4 行](../design/API.md) · [数据模型 M4 DDL 与并发规则](../design/DATA_MODEL.md) · [架构中的账户与会话](../design/ARCHITECTURE.md#安全与信任边界) · [产品范围](../design/PRODUCT.md)。实现中发现契约要改，先改设计文档再改代码。

开工顺序：M4-01 → M4-02 → M4-03 → M4-04 → M4-05。每个切片可单独合并和验收，不跨切片夹带改动。

分工（沿用 [AGENTS.md](../../AGENTS.md)）：Codex 负责后端、接口、数据库和迁移；Claude 负责 `frontend/`、设计与任务文档、E2E 场景。两者不同时改同一份工作区。

通用约束：
- 不引入 P1 代理、P2 客户端或额外中间件。
- 新增核心依赖（例如 Spring Security）前先停止，列出备选方案等确认。
- 测试不调用真实模型，默认使用 mock。
- 每个切片按 [项目协作约定](../../AGENTS.md#完成标准)交付一份本地报告，记录真实命令、退出码、测试数量、失败与未验证项。

## M4-01：账号与登录会话

- 状态：DONE（本地验收；已经 PR #1 合入 `master`）
- 分工：Codex（用户表迁移、预建账号、登录、退出、CSRF、`/api/me`）；Claude（登录页、CSRF 请求头、未登录时的 401 处理）
- 前置：无（基线 master `e2fb7e2`）
- 设计依据：API 的 `GET /api/auth/csrf`、`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/me`；DATA_MODEL 的 `users` M4 DDL；ARCHITECTURE「账户与会话」
- 要改的文件（预估）：后端 auth 相关包、新的 Flyway 迁移、配置与测试；`frontend/src/` 中的登录入口与请求封装
- 范围：
  - `users` 增加 `email_normalized`、`password_hash`、`state` 与唯一索引
  - 预建账号通过受控的本机命令或配置写入，密码与哈希不进仓库、日志或测试 fixture
  - 登录成功返回 204 并轮换会话 ID；退出返回 204 并使会话失效
  - 只有 ACTIVE 用户能登录；DISABLED、错误密码、不存在的邮箱返回同一提示
  - 登录限速；登录和退出校验 CSRF；`/api/me` 无有效会话返回 401
  - M1–M3 的显式本地测试主体保持不变，现有测试和 E2E 不回归
- 非目标：注册、找回密码、设置、草稿、运行历史
- 测试：
  - 邮箱规范化与唯一冲突
  - 登录成功 204，Cookie 带 Secure、HttpOnly、SameSite=Lax
  - 错误密码、未知邮箱、DISABLED 返回同一提示
  - 限速生效
  - 退出后会话失效
  - CSRF 缺失被拒绝
  - `/api/me` 无会话返回 401
  - 登录后会话 ID 已变化
- 验收：`./mvnw -B -ntp clean verify` 退出 0；E2E 覆盖登录后 `/api/me` 为 200、退出后为 401；M1–M3 的 E2E 全部通过

## M4-02：用户设置与草稿

- 状态：DONE（前端草稿与 revision 冲突本地验收；设置页未接入）
- 分工：Codex（`user_settings`、`drafts`、`GET/PATCH /api/settings`、`GET/PUT /api/problems/{problemId}/draft`）；Claude（草稿改为服务端保存，revision 冲突提示，旧版草稿的复制入口）
- 前置：M4-01
- 设计依据：API 的 settings 与 draft 行；DATA_MODEL 的 `user_settings`、`drafts` DDL 与「草稿」并发规则
- 要改的文件（预估）：后端 settings 与 draft 包、迁移、测试；`frontend/src/practice/` 中的草稿读写
- 范围：
  - `GET/PATCH /api/settings`：locale 与编辑器偏好白名单，PATCH 返回保存后的记录
  - `GET /api/problems/{problemId}/draft`：可带 version，缺省取当前版；无草稿返回 `draft: null`
  - `PUT`：明确 version、caseId、slots、revision；不存在时用 revision 0 创建为 revision 1，返回 201；已有时带精确 revision 更新并递增，返回 200
  - revision 不匹配返回 409，并附服务器当前 revision；客户端先保留本地编辑
  - 不同题目版本的草稿可并存；旧版草稿可读取，复制到当前版由用户主动触发
  - 草稿跨刷新保留（M3-03 中留到 M4 的部分）
- 非目标：草稿的离线合并、多设备冲突自动合并
- 测试：
  - 无草稿时 GET 返回 `draft: null`
  - 创建 201、更新 200
  - revision 不匹配 409 并返回服务器 revision
  - 两个并发写者只有一方成功
  - 不同 version 草稿并存
  - PATCH 白名单外的字段被拒绝
  - 用户 A 不能读写用户 B 的草稿与设置，跨账号资源返回 404
- 验收：后端测试通过；E2E 中修改草稿后刷新，内容仍在；revision 冲突时页面保留本地编辑

## M4-03：运行历史与归档

- 状态：DONE（本地，前端历史与归档已接入）
- 分工：Codex（`GET /api/problems/{problemId}/runs` 分页、`POST/GET /api/submissions`、`DELETE /api/submissions/{submissionId}`）；Claude（历史列表、归档与取消归档按钮、归档后的状态展示）
- 前置：M4-01
- 设计依据：API 的 runs、submissions 行与列表游标规则；DATA_MODEL 的 `submissions` DDL、归档语义；PRODUCT「学习记录」一行
- 要改的文件（预估）：后端 history 与 submission 包、迁移、测试；`frontend/src/practice/` 与 `app/App.vue` 中的历史入口
- 范围：
  - 历史列表：本人跨版本，按时间倒序分页，列表只含摘要；游标绑定排序与筛选，读取始终带当前主体
  - 归档：`POST /api/submissions` 传 runId，只能归档本人且 COMPLETED 的运行；同一 runId 重试返回原归档，201 或幂等 200
  - 列表不返回模型原文或完整快照，运行详情字段白名单不变
  - 取消归档：DELETE 只删除归档标记，运行本身保留，成功返回 204
  - 归档不调用模型
- 非目标：批量归档、归档搜索、历史统计
- 测试：
  - 归档他人运行、归档非 COMPLETED 运行均被拒绝
  - 同一 runId 重试返回原归档
  - 归档过程中模型调用计数为 0
  - 取消归档后运行仍可读
  - 游标在翻页中稳定，不跨用户泄露
  - 列表响应不含模型原文字段
  - 数据库忙超时映射为 503
- 验收：后端测试通过；E2E 中归档后列表可见，取消归档后列表消失，运行详情仍可打开

## M4-04：账号隔离、留存与备份

- 状态：DONE（后端本地验收；浏览器侧未覆盖留存与停用）
- 分工：Codex（留存清理、账户停用与撤销会话、数据删除、`VACUUM INTO` 备份与恢复脚本）；Claude（运维说明、`docs/TESTING.md` 的验收项）
- 前置：M4-03
- 设计依据：DATA_MODEL「删除与留存」与「过期」；ARCHITECTURE「备份」；ROADMAP 中 M4 的验收描述
- 要改的文件（预估）：后端维护任务、运维命令、备份脚本、测试；`docs/TESTING.md`、`docs/` 运维说明
- 范围：
  - 留存清理以快照为入口，级联删除运行；已归档的运行不被清理
  - 维护任务把超时的 PENDING 小批量 CAS 为 EXPIRED，`finishedAt` 取截止时间
  - 清理与归档由短写事务序列化；清理前在同一事务重查归档不存在
  - 账户停用后撤销会话，业务 API 拒绝访问；受控运维流程可删除该账户的关联数据
  - 备份：`VACUUM INTO` 输出到新文件，完整性检查，在独立目录恢复后做外键与行数检查，并读取关键业务数据
- 非目标：自动备份调度、异地备份、对象存储
- 测试：
  - 清理不删除已归档的运行
  - 过期 PENDING 转为 EXPIRED，过期后不接受新终态
  - 清理与归档并发时结果一致
  - 停用账户后已有会话失效
  - 备份可在独立目录恢复，外键与行数检查通过
- 留存策略：未归档的终态或过期运行保留 30 天，已归档运行和草稿不定时清理。每日备份，默认保留最近 7 份。[运维步骤](../guides/DATA_OPERATIONS.md)
- 验收：清理、停用、备份恢复各有测试；备份恢复在独立目录实跑，记录命令与结果
