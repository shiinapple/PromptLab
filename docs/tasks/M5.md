# M5 任务

目标：完成 UI 中英双语与语言偏好同步、首次使用与故障切换引导、窄屏响应式布局及可访问反馈，使受邀用户能够独立完成 D0 与支持的直连流程，且切换语言不丢失当前草稿。

退出门槛：用户可以独立完成 D0 与支持的直连流程，语言切换不丢草稿（见 [路线图](../ROADMAP.md)）。

契约：[全站导航与页面交互](../design/UI.md) · [产品范围](../design/PRODUCT.md) · [工程结构与信任边界](../design/ARCHITECTURE.md) · [REST API 与错误协议](../design/API.md) · [数据模型](../design/DATA_MODEL.md) · [模型接入与安全](../design/MODEL_INTEGRATION.md) · [已定决策](../DECISIONS.md)。实现中若发现契约需要调整，先改文档再改代码。

开工顺序：M5-01 → M5-02 → M5-03 → M5-04 → M5-05。M5-03 与 M5-04 都依赖 M5-02 的词条机制，可以串行，也可以分分支推进；若并行，先合入 M5-03 的引导组件，再做 M5-04 的响应式改造，避免 `App.vue` 与 `ManualRunSection.vue` 冲突。M5-05 在前四个切片完成后做无障碍与端到端总验收。

分工：按 [AGENTS.md](../../AGENTS.md) 与 [D15](../DECISIONS.md)，M5 以前端为主，由 Claude 负责 `frontend/`、样式取值与文档更新；Codex 仅在需要补充后端契约或错误 `messageKey` 映射时介入。M5 原则上不新增后端接口，也不改数据库表结构。Claude 与 Codex 不同时改同一份工作区。

通用约束：
- 不引入 P1 代理、P2 客户端、视觉题 003 或额外中间件（[D08](../DECISIONS.md)、[D10](../DECISIONS.md)）。
- 新增核心依赖前必须暂停相关改动，待所有者在文末「待所有者确认」拍板后再接入，不得擅自写入 `frontend/package.json`。已批准的依赖：`vue-i18n`（见第 3 项结论）；无障碍检测库未批准。
- 样式值（颜色、间距、圆角、焦点样式等）统一取自 `frontend/src/styles/tokens.css`（[D16](../DECISIONS.md)），不在组件里硬编码新颜色或新间距。需要新增 token 时，由 Claude 作为前端负责人决定，统一合入 token 文件，并在切片报告中列出。
- 测试默认使用本地 mock，不发起真实模型请求，不使用真实 API Key，真实 Key 不进入仓库、日志或报告。
- E2E 沿用现有 `frontend/test/practice.e2e.mjs` 的本机 Chrome（CDP，`CHROME_BIN` 可指定路径）方式，不新增浏览器自动化依赖。
- 新增单元测试文件须命名为 `frontend/test/*.test.mjs`，否则 `npm --prefix frontend test` 不会执行。
- 每个切片完成时，按 [项目协作约定](../../AGENTS.md#完成标准) 在 `docs/personal/reports/milestones/` 下产出独立交付报告，文件名为 `YYYY-MM-DD-m5-0X-<主题>.md`（不进 Git，公开文档不链接），记录真实命令、退出码、测试数量、失败项与未验证项。

- 范围：
  - 将现有仅在启动时读取 URL `?locale=en` 的静态写法替换为响应式 `zh-CN` / `en` 切换状态，切换时同步更新 `document.documentElement.lang`。
  - 在顶栏提供中文 / English 切换入口。切换按钮自身用对方语言的名称标注（显示 “English” 或 “中文”），便于识别。
  - 语言来源优先级（默认方案，实施时可在验收前调整）：
    1. URL `?locale=` 仅对本次页面加载生效，不写回 `user_settings`；
    2. 已登录用户以 `GET /api/settings` 返回的 `locale` 为准；
    3. 未登录时使用浏览器本地存储（非敏感配置），缺省为 `zh-CN`。
  - 登录后若服务端 `locale` 与本地存储不一致，以服务端为准并更新界面语言。
  - 用户切换语言时调用 `PATCH /api/settings` 持久化 `locale`。保存失败时保留本次切换的界面语言，并以 `role="alert"` 提示保存失败，不静默回滚，也不改动草稿。未登录时只写本地存储，不调用 `PATCH`。
  - 切换语言时重新请求当前题目的展示文本（`GET /api/problems/{problemId}?locale=...`），仅替换题面、说明等展示字段。以下内容必须保持不变：
    - 编辑器中未保存及已保存的 Prompt 草稿（逐字符一致）；
    - 当前选中的 `caseId`；
    - 当前运行快照，不重新触发推理，不替换旧运行记录。
  - 切换语言不得触发草稿 `GET`/`PUT`，不得改变草稿 `revision`。
- 非目标：不引入第三方翻译服务；不新增除 `zh-CN`/`en` 外的语言；不翻译用户自己编写的 Prompt 内容；不修改后端题库结构或数据库迁移；不做 P1/P2。
- 测试：
  - 单元测试（`*.test.mjs`）：语言状态切换、`html[lang]` 更新、词条回退逻辑、语言来源优先级、`PATCH /api/settings` 成功与 503/网络失败分支（失败时草稿与语言保留）。
  - E2E（mock）：在做题页输入未保存的 Prompt 草稿后切换 `zh-CN` ↔ `en`，验证草稿文本逐字符不变、选中 `caseId` 不变、请求预览与已冻结运行不受影响，且草稿相关请求数为 0；刷新页面后语言与 mock `GET /api/settings` 保持一致。
- 验收：
  - 顶栏可一键切换中文与 English，无需刷新整页即可更新页面语言与 `document.documentElement.lang`。
  - 切换语言前后，编辑器内 Prompt 草稿内容逐字符一致，未发出额外模型请求，未发出草稿请求。
  - 刷新页面后，界面语言与 `user_settings.locale` 一致（已登录）。
