# 开发路线

正式架构评审通过后开始 M0。PoC 根据其影响进入对应的实施或发布任务，执行证据仍归入 [验证文档](TESTING.md#poc-后续安排)。项目进度见 [STATUS](STATUS.md)，各任务状态由 [tasks](tasks/README.md) 维护。

| 阶段 | 交付顺序 | 退出门槛 |
|---|---|---|
| [M0](tasks/M0.md) | 01 全新 Java/Maven 与 Vue/TS/Vite 工程 → 02 同源代理和健康检查、03 SQLite 迁移基线 → 04 验收 | 架构确认后开工；从干净检出完成构建、类型检查、启动、同源 API 与迁移集成测试。记录锁定版本和命令。 |
| [M1](tasks/M1.md) | 002 题目包 → 组装与判题 → 快照/结果 REST → D0 做题页 | 本地读题到判题可演示。POC-05 放入判题任务，POC-06 的 D0 部分放入导入导出，集成验证所有权、幂等和状态竞争。 |
| [M2](tasks/M2.md) | 本地模型配置 → 普通 → SSE/取消 → CSP 候选、切换与回归 | POC-01/02 Mock 证据可复用，正式 SPA 在本地 Mock 下走通；补齐 POC-06 的四来源一致性。实际网关上线前验收。 |
| M3 | 001 与 002、多公开用例、历史版本及双语资源 | 共用做题页，题库 lint 阻止版本覆盖与规则错误。 |
| M4 | 预建账号、会话、CSRF、草稿、历史/归档与留存 | 真实账号隔离、revision、归档、数据删除与备份周期可验收。M1–M3 测试主体仅本地使用。 |
| M5 | UI 双语、引导、窄屏和可访问反馈 | 用户可以独立完成 D0 与支持的直连流程，语言切换不丢草稿。 |
| M6 | 集成、真实 HTTPS、性能、安全、备份恢复、回滚预演 | 确认内测支持矩阵、资源和安全约束、恢复窗口。真实模型只在明确授权后调用。 |
| M7 | Nginx + systemd + HTTPS 发布 | 正式主机冒烟、数据/进程权限、日志与告警、实际回滚路径验收后开放内测。 |
| 独立后续 | 003 视觉题、P1/P2 需求评审 | 003 通过 POC-07 才开放；P1/P2 仅在实际需求影响首版路径时复审。 |

任务状态维持 TODO / IN_PROGRESS / BLOCKED / DONE。DONE 以对应验收证据为准。工程设计细节按任务验证推进，所有者只需集中处理 [产品和发布决策](DECISIONS.md#待确认原稿--审查新增建议)。
