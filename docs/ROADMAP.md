# 开发路线

本规划在原稿实施顺序上提出垂直切片调整，未改变公开 MVP 需求。正式工程尚未初始化，PoC 进度见 [TESTING](TESTING.md)。M1/M2 的无认证开发形态只允许本地，不得公网发布。

| 阶段 | 目标 | 依赖 | 退出门槛 |
|---|---|---|---|
| POC | 验证直连、安全、SQLite、判题、D0 | 本机 Mock 先行；真实阶段需 Q01 目标及授权 | 有真实证据；通过或批准降级，未测明确记录 |
| M0 | 工程骨架、构建、测试、迁移、同源本地开发 | POC 栈通过 | 前后端启动、构建与最小测试通过；不含真实功能 |
| M1 | 样题 002 D0 最小闭环 | M0、POC-04/05、状态/模板决策 | 读题→编辑→冻结→导出→导入→Java 判题→反馈；失败路径有测试 |
| M2 | 浏览器直连 | M1、POC-01/02 | 同一判题通路支持普通/SSE/取消、Key 隔离和 D0 兜底 |
| M3 | 题库与多用例 | M1/M2 | 001/002 共享页面，内容 lint、版本及公开用例；003 独立验证后开放 |
| M4 | 账户、草稿与学习记录 | M1–M3 | 登录/会话/CSRF、账号隔离、revision、归档/留存；预建账户、邀请内测（Q02） |
| M5 | UI 完善、中英、操作引导 | M2–M4 | 新用户可完成练习；语言不覆盖草稿；可访问状态和窄屏布局 |
| M6 | 发布前验证 | M0–M5 | 安全/性能/E2E/备份恢复及已知风险审查 |
| M7 | 部署 | M6 | Nginx + systemd + HTTPS、监控、回滚、同规格验收 |

P1/P2 为后续产品评审，不属于 M0–M7 默认范围。文字题先发布，视觉题经独立验证后开放。

## 执行顺序

1. 四项设计决策已确认，见 [DECISIONS](DECISIONS.md)。
2. POC-01 先运行本机浏览器 Mock，再由真实 HTTPS 测试站访问用户授权的目标网关。POC-03/04/05 可独立推进，POC-02 与直连联动。
3. 汇总证据，确定依赖、限制和接入范围；必要时在 Chat 中更新设计。
4. 完成 M0，再按 TASKS 中 M1 → M2 依赖推进。
5. 每个任务一个可审查 diff；里程碑通过后再提交标签（由用户决定）。
6. M3 以后依据实际实现细化任务，不提前设计所有字段。

任务状态：TODO / IN_PROGRESS / BLOCKED / DONE。DONE 要有验收证据；文档设计完成不代表实现完成。
